# Toolchain Upgrade Warnings

Status: implemented.

## Goal

Make the workspace green again under `moon 0.1.20261104 (940aa18)`:
`moon fmt --check`, `moon check --deny-warn`, `moon test --deny-warn`
(native and wasm) and the `moon info` + `git diff --exit-code` gate must
pass with no warnings. The upgrade produced 36 warnings and no errors.

## Context and decisions

The upgrade adds two diagnostics to code that was accepted before.

1. `deprecated_syntax` (E0027), 26 sites: `} derive(Eq, Debug)` and
   `struct KeyModifiers(Int32) derive(...)` are deprecated in favour of
   `#derive(...)` above the declaration. `moon fmt` already emits exactly
   this rewrite, so the migration is mechanical and semantic-free. The
   generated `.mbti` files already carried the new spelling in the working
   tree; they are regenerated with `moon info` and committed here.
2. `cancellable_defer` (E0098), 10 sites: `defer`/`errdefer` bodies are now
   checked for cancellable async calls. The old helper-level idiom stopped
   working because `protect_from_cancel` changed: `moonbitlang/async@0.21`
   took `resume_on_cancel?`, `@0.22.4` returns a `nocancel` effect instead.
   That effect is not inferred through user-defined async functions, so
   `defer helper()` warns even when `helper` protects its own body.

Decisions:

- Keep the demo and test call sites as they are — `defer tty.close()` stays
  literally unchanged — and state the guarantee in the effect signature:
  `Sidecar::wait` and `Tty::close` become `nocancel`. `Sidecar::wait`
  already wraps its entire body in `protect_from_cancel`
  (`Reaping is not cancellable: a cancelled first call would leave a
  zombie`), and `Tty::close` only adds two sync trait `close` calls, so
  this records existing behaviour instead of changing it.
- The effect has to be stated from the inside out: a `nocancel` function
  may not call a cancellable async function (E4227), so `Sidecar::wait`
  must become `nocancel` before `Tty::close` can.
- `async fn Tty::restore_raw_mode` is private and already protects its
  body; it becomes `nocancel` too, which covers `defer` in
  `Tty::with_raw_mode`.
- `Tty::leave_raw_mode` keeps its signature: it is public API and only one
  demo line defers it, so that line protects itself.
- `errdefer remove_temp_dir(dir)` in `internal/sidecar/locate.mbt` protects
  its own call: `remove_temp_dir` is a private async helper doing real
  filesystem work and retries, and nothing else needs the effect.
- No `#warnings("-98")` suppression: it would also hide the check for a
  cancellable step added to `Tty::close` in the future, which is the case
  the diagnostic exists for.

## Public API changes

| item | before | after |
| --- | --- | --- |
| `Tty::close` | `pub async fn Tty::close(Self) -> Unit` | `... -> Unit nocancel` |
| `Sidecar::wait` (internal package) | `pub async fn Sidecar::wait(Self) -> Unit` | `... -> Unit nocancel` |

Nothing is added, removed or made visible. The generated `.mbti` otherwise
differs only by the `#derive(...)` spelling.

External consumer story: direct calls, `defer`, and passing a `nocancel`
function to an `async () -> Unit nocancel` parameter all keep working.
`nocancel` is not a subtype of a cancellable effect, so a caller that passes
`Tty::close` as a plain `async () -> Unit` value would no longer compile.
The workspace contains no such use. The effects change no behaviour: they
record what the code already did. The one runtime change in this commit is
on cancellation paths — the two locally protected defers below now finish
their cleanup instead of aborting mid-flight, which is what that cleanup is
for.

## Invariants

- `Tty::close` still reaps the sidecar and removes its temporary directory
  on every path, including a cancelled task.
- `defer tty.close()` keeps its current runtime semantics; only the type
  signature learns about the guarantee.
- Closing remains idempotent (`closed` / `reaped` flags unchanged).

## Acceptance criteria

- `moon fmt --check` is clean.
- `moon check --deny-warn` is clean for native and wasm.
- `moon test --deny-warn` passes for native and wasm.
- `moon info` leaves the tree unchanged (`git diff --exit-code`), as CI

## Validation

Run on macOS arm64 with `moon 0.1.20261104 (940aa18 2026-11-04)`:

- `moon fmt`, `moon fmt --check`: exit 0.
- `moon check --deny-warn`: exit 0, 0 warnings (36 warnings before the change:
  26 `deprecated_syntax` and 10 `cancellable_defer`).
- `moon check --target wasm --deny-warn`: exit 0, 0 warnings.
- `moon test --deny-warn`: 213/213 passed.
- `moon test --target wasm --deny-warn`: 208/208 passed.
- `moon info` twice: the second run leaves `git diff` unchanged, so the
  generated interfaces match the sources and CI's `git diff --exit-code`
  gate stays green.
- `git diff --check`: clean.

Windows is covered by CI only, as before.

## Public API audit

- Reviewed `Tty::close` and `internal/sidecar` `Sidecar::wait`: both gain
  only a `nocancel` effect, no visibility or signature-arity change.
- `Tty::restore_raw_mode` and `remove_temp_dir` stay private, so the
  generated root and internal interfaces do not mention them.
- `.mbti` regenerated with `moon info` and reviewed after the migration;
  the only textual change beyond `#derive(...)` is the two `nocancel`
  effects.

## Result notes

The warning count went from 36 to 0. The three `nocancel` effects change no
behaviour: they describe what the code already did — `Sidecar::wait` wraps
its whole body in `protect_from_cancel`, and `Tty::close` only adds two sync
trait `close` calls on top of it. `examples/*` demos keep their original
`defer tty.close()` lines; the only demo edit is the `leave_raw_mode` defer
in `examples/raw`, which protects its own call.

The one runtime change is on cancellation paths, and it is the point of
the two local protections: `leave_raw_mode` in `examples/raw` and the
temporary-directory removal in `internal/sidecar/locate.mbt` used to be
interruptible mid-flight (terminal left raw, temporary directory left
behind) and now always run to completion before cancellation resumes.
