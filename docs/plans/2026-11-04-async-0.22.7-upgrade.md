# Upgrade `moonbitlang/async` to 0.22.7

Status: implemented.

## Goal

Move every module in this repository from `moonbitlang/async@0.22.4` to the
latest published release, `0.22.7` (registry index, published 2026-10-30),
and keep the workspace on a single async version.

## Context and decisions

- The upgrade is a version-only change. Comparing the public interfaces of
  every async package this repository imports (`async`, `fs`, `io`, `pipe`,
  `stdio`, `types`, `process`, `os_error`, `aqueue`, `semaphore`) between
  0.22.4 and 0.22.7 shows one systematic delta: the async API migrated its
  `Int` spellings to `Int32` (`sleep`, `with_timeout`, `Fd`, `File::fd`,
  `wait_pid`, `errno_*`, `Semaphore`, ...). The two are aliases today, so no
  call site changes; the new `fs` helpers (`Directory::open`,
  `Directory::remove`, `symlink`, relative open) are additions this
  repository does not use yet.
- All six module pins are bumped together — root, `examples`, `tests`,
  `tests/open`, `tests/isatty`, `tests/resize` — following the single-version
  rule recorded for DEP-1.
- Versions are written by `moon add --upgrade moonbitlang/async`, not by
  hand, so the pins come from the registry index.

## Target files

- `moon.mod`, `examples/moon.mod`, `tests/moon.mod`, `tests/open/moon.mod`,
  `tests/isatty/moon.mod`, `tests/resize/moon.mod`: the dependency pin.
- `docs/plan.md`, this plan.

No source, manifest option, or generated interface changes.

## Public API changes

None. `moon info` leaves every `pkg.generated.mbti` unchanged: this package's
own interface names async types (`@async/types.Fd`, `@io.Data`, ...) instead
of expanding them, so the `Int` -> `Int32` migration inside async does not
surface here.

## Invariants

- Every module in the repository pins the same `moonbitlang/async` version.
- Raw mode, resize and sidecar behaviour are unchanged; the bump does not
  alter the runtime this package uses.

## Acceptance criteria

- `moon fmt --check`, `moon check --deny-warn` (native and wasm),
  `moon test --deny-warn` (native and wasm) pass with no warnings.
- `moon info` leaves the tree unchanged.
- The three nested test modules (`tests/open`, `tests/isatty`,
  `tests/resize`) still type-check against the new version.

## Validation

Run on macOS arm64 with `moon 0.1.20261104 (940aa18 2026-11-04)`:

- `moon update`: registry and symbols updated.
- `moon check --deny-warn`: exit 0, 0 warnings.
- `moon check --target wasm --deny-warn`: exit 0, 0 warnings.
- `moon test --deny-warn`: 213/213 passed.
- `moon test --target wasm --deny-warn`: 208/208 passed.
- `moon check` in `tests/open`, `tests/isatty`, `tests/resize`: exit 0.
- `moon info`: no `.mbti` diff; `moon fmt --check`: clean.

Windows is covered by CI only, as before.

## Public API audit

- `pkg.generated.mbti` is byte-identical after the bump.
- No `pub` item, type, trait bound, or effect changed.
- The dependency itself is still experimental upstream (`moonbitlang/async`
  0.22.7 marks its API subject to change), which is unchanged from 0.22.4.

## Result notes

A one-line edit per module, validated on both targets. The sidecar, raw mode
and input-decoding paths are untouched.

## Open questions

- Upstream's 0.22.7 README states that `moonbitlang/async` will eventually be
  replaced by `moonbitlang/core/async` in the standard library, that the two
  share one runtime, and that they can be mixed for incremental migration.
  `moonbitlang/core/async` is not ready for that switch here: it has no
  `@async/io.Data`, `Reader`, `Writer` or `ReaderBuffer` — the abstractions
  this package's public traits and buffering are built on — and its
  `read_text`/`write_text`/`run` replace the `read_file`/`write_file`/
  `collect_stdout` helpers used by the sidecar. Migrating therefore changes
  public API (see the discussion recorded for that task) and is deliberately
  not part of this bump.
